# TypeScript Role Surfaces Implementation Plan

**Goal:** Idiomatic, typed TypeScript APIs shaped by role — `Requester`, `Consumer`, `Runtime`, `Agent` — with the same behavior as the Python runtime.

**Architecture:** The kernel (`json`, `parse`, `crypto`, `schema`, `decision`, `state-machine`, `signing`) stays protocol-only. The role surfaces add ergonomics: `Requester` signs manifests/signals, `Consumer` verifies and produces permission cards, `Runtime` enforces grants with two-phase confirmation, `Agent` wraps tool calls and checks attenuation.

**Tech Stack:** TypeScript 5, ESM, Vitest, `@noble/ed25519`, `@noble/hashes`.

**Spec:** `CCP_Working_Draft_v0.5.md`; contract: `test-vectors/`.

## Global Constraints

- All 51 frozen vectors stay green.
- `src/` runs in browser and Node (no `fs`, `path`, `Buffer`, `process`).
- Wire field names stay snake_case (§10.1/§26.1); method names are camelCase.
- Runtime semantics match the Python suite (authorized, confirmation, replay, limits, lifecycle, failures).
- Commit only when the user asks.
